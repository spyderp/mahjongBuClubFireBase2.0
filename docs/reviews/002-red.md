# 002-red.md — Experimento previo de la red (T42)

Resultado del experimento acotado que `specs/002/plan.md` §6.5 y la tarea **T42** exigen **antes** de
comprometerse a escribir `offline.test.ts`. El propio plan avisa de que este es el único criterio de la
especificación que puede no cumplirse, y de que un criterio retirado con motivo es mejor que un test que
se salta sin que nadie lo note.

**Fecha:** 2026-10-15 · **Método:** un fichero de test desechable bajo `happy-dom`, ejecutado y borrado.

## Veredicto

**No es alcanzable en este repositorio.** El criterio 26 de `specs/002/spec.md` —«RNF-5 de 001 tiene un
test que corta la red: se registra un turno sin cobertura y sincroniza después»— **queda declarado fuera
de alcance**, y **T43 queda descartada con este motivo**. No se da por cumplido.

## Las cuatro mediciones

| # | Medición | Resultado |
| - | -------- | --------- |
| A | ¿Hay `indexedDB` en `happy-dom`? | **`undefined`** |
| B | ¿Se puede construir `persistentLocalCache()`? | Sí, devuelve `{kind: 'persistent'}` — es un descriptor perezoso, no abre nada |
| C | ¿Hay emulador? `FIRESTORE_EMULATOR_HOST` | **`null`**, no configurado |
| D | Sin backend, ¿una escritura se encola o se rechaza? | **Sale a internet de verdad** y vuelve `PERMISSION_DENIED` de `firestore.googleapis.com` |

El log del propio SDK en la medición D es la prueba que cierra el experimento:

```
@firebase/firestore: Firestore (12.19.0): Error using user provided cache. Falling back to memory cache:
FirebaseError: [code=unimplemented]: This platform is either missing IndexedDB or is known to have an
incomplete implementation. Offline persistence has been disabled.

@firebase/firestore: Firestore (12.19.0): GrpcConnection RPC 'Write' stream error. Code: 7
Message: PERMISSION_DENIED: Cloud Firestore API has not been used in project 'experimento' before
```

## Los tres motivos, por separado

**1. `happy-dom` no trae `indexedDB`, así que la caché persistente no existe.** Es la razón de que
`src/app/firebase.ts` pase `persistentLocalCache()` y el SDK lo descarte en silencio, bajando a caché en
memoria. El propio SDK lo dice: *Offline persistence has been disabled*. En un test no hay forma de
observar «una escritura se encola y luego sincroniza», porque la mitad del mecanismo —la cola persistente—
no se ha creado.

**2. No hay servidor al que «llegar».** El criterio tiene dos mitades: *se registra sin cobertura* y
*sincroniza después*. La segunda mitad es **inobservable** sin un backend. `FIRESTORE_EMULATOR_HOST`
está vacío, que es exactamente la condición que hace que `firestore.rules.test.ts` se salte su bloque
del emulador. Sin emulador, la mitad comprobable del criterio se queda sin objeto.

**3. El test no sería hermético.** La medición D salió a internet: `happy-dom` deja pasar `fetch`, así que
una escritura sin emulador **ataca `firestore.googleapis.com` de verdad** y depende de credenciales y de
red del entorno. Un test que depende de Google es peor que un test ausente.

## Lo que esto **no** dice

No dice que la captura sin conexión esté rota en la aplicación. Dice que **no es comprobable aquí**. Las
tres cosas que sí sostienen RNF-5 en producción siguen en pie y están comprobadas por otros medios:

- `src/app/firebase.ts` configura `initializeFirestore` con `persistentLocalCache`, y `firebase.test.ts`
  comprueba esa llamada.
- La re-derivación ocurre en cliente, en `domain/replay.ts`, que es puro: **no toca la red**. `RNF-4`
  —«re-derivar un turno no puede exigir red»— queda cumplido por construcción, y `replay.test.ts` lo
  demuestra al no tener ninguna dependencia de Firebase.
- La escritura encolada usa el mismo camino que cualquier otra escritura, y `useGameTurns.test.ts`
  comprueba que `correctTurn` abre **un único `WriteBatch`**, que es la parte de RNF-5 que sí es observable
  sin red (atomicidad).

## Qué haría falta para reabrirlo

Las tres, no una:

1. Un emulador de Firestore levantado en el entorno de pruebas, que ya es la condición que el propio
   repositorio reconoce en `firestore.rules.test.ts`.
2. Un entorno con `IndexedDB` real para `happy-dom`, o cambiar ese fichero a `// @vitest-environment node`,
   que es lo que ya hace `firestore.rules.test.ts`.
3. Bloquear `fetch` en el test, para que ninguna medición vuelva a salir a internet.

Con las tres, T43 se vuelve alcanzable sin tocar la aplicación. Hasta entonces, `offline.test.ts` sería un
test que no puede pasar de verdad, y un test así es peor que no escribirlo.
